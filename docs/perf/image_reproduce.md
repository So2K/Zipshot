# Reproduce the image measurements

Use Windows x64 with Visual Studio C++ Build Tools. Outputs stay under ignored `build/perf/images`; fixtures contain only generated pixels. Timing processes use below-normal priority and affinity0xF. Do not run competing benchmarks concurrently. No desktop, user gallery, installed settings or host clipboard is used.

Production encoder checks require no download: pinned fpng is already in `third_party/fpng`. Run `tools\perf\image_fpng_quality.bat` and its `--scalar` variant, then `tools\perf\image_build.bat`. The prepared-packet checker requires a fresh output directory passed to `build\perf\images\image_prepared_check.exe`.

The optional comparative encoder tool also needs FPNGE sources. Run `python tools/perf/image_fetch_vendor.py` to fetch SHA-verified sources pinned by `image_vendor_pins.json` into ignored build output, then `tools\perf\image_fastpng_build.bat`. Pins are fpng925796543b9d26b8edfcdcecd94c1dac280f29fc (Unlicense, license text retained in source) and FPNGE097ebccf3d3db443d9a8f238b1deed010a82f961 (Apache-2.0, LICENSE fetched). FPNGE is an optional encoder comparison and is not an application dependency. AVX2/SSE4.1 candidate calls have CPU/OS capability checks. The retained comparative tool encodes and verifies through trusted WIC; retired experimental reader code is preserved only in ignored experiment evidence.

Official ShareX comparison requires the unmodified22.4.0 portable runtime, default source directory `D:/ZipshotRuntimeCompare-20261118/vendor/ShareX-22.4.0-portable-x64`. `tools/perf/image_sharex_build.ps1 -ShareXDir <path>` builds our CLI and copies runtime DLLs/configuration to an isolated ignored folder; it never replaces files in that source directory. The own entry point invokes the actual stock codecs, not ShareX application startup. See [source/timing explanation](image_stock_path.md).

`python tools/perf/image_profile.py --n 20 --out build/perf/images/corpus-new` generates the broad baseline/encoder comparison. `tools/perf/image_production_build.bat` followed by `python tools/perf/image_production_profile.py --n 20 --corpus build/perf/images/corpus-new --out build/perf/images/production-new` measures actual production file-save APIs against the stock methods. Use fresh corpus and output directories when code changes; completed runs are reused. The original stored corpus is historical baseline data; its source/executable hashes are recorded, and reproducing on newer code produces a new run rather than replacing the old measurements.

`image_wic_native_build.bat` builds a frozen original1fdf0a7 WIC loader reference against the actual current production loader. The final recorded49-file matrix and bounded converter follow-up are ordinary known-good differential checks, including transparency/color-key/palette/gray16 and stock32-bit PNGs. Do not infer cold startup from the first timed row. No unsafe third-party-reader or malformed-file experiment is included in this workflow.
